# Обязательные правила работы с проектом Portfolio Ekaterina

## СТАРТОВЫЙ ПРОТОКОЛ

При начале ЛЮБОЙ работы (включая после компактинга контекста) выполни по порядку:

1. **Прочитай `docs/STATE.md`** — там карта всех блоков, их статусы, последние изменения и критические ограничения
2. **Прочитай `docs/BACKLOG.md`** — там тикеты с привязкой к блокам
3. **Прочитай `docs/DESIGN_SYSTEM.md`** — цвета, шрифты, компоненты, текстуры
4. **Напиши пользователю:** "Прочитал STATE.md. Текущий блок в работе: [название]. Тикет: [номер]"

## ОБЯЗАТЕЛЬНЫЕ УТОЧНЯЮЩИЕ ВОПРОСЫ

Перед началом ЛЮБОЙ работы задай МИНИМУМ 1 уточняющий вопрос. Примеры:
- "Ты имеешь в виду удалить или закомментить?"
- "Я правильно понял — трогаем ТОЛЬКО этот блок, остальные не трогаем?"
- "Когда ты говоришь 'всё на месте' — это значит ок или проблема на месте?"

НЕ НАЧИНАЙ работу пока не получишь подтверждение.

## ЗАПРЕТЫ

- ❌ НЕ трогай блоки со статусом ✅ Готов без явного запроса пользователя
- ❌ НЕ используй код, стили или решения из `portfolio-website` или любого другого проекта
- ❌ НЕ комментируй и не удаляй компоненты, которые тебя не просили трогать
- ❌ НЕ додумывай за пользователя. Сомневаешься — спроси

## GIT-ДИСЦИПЛИНА

- Перед началом работы: `git add -A && git commit -m "snapshot: before TICKET-XX"`
- После завершения: `git add -A && git commit -m "feat(TICKET-XX): описание"`

## ОБНОВЛЕНИЕ ДОКУМЕНТАЦИИ

В конце каждой рабочей сессии обнови:
- `docs/STATE.md` — статусы блоков, лог изменений
- `docs/BACKLOG.md` — статусы тикетов
