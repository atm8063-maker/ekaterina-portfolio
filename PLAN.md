# PLAN — Довести до релиза (Ekaterina Portfolio)

> STAGE-план по методологии project-brain (grill → **spec** → tickets → implement → retro).
> Организационные решения по проекту — `project-brain/ekaterina-portfolio/DECISIONS.md`.
> Технический бэклог и статус блоков — `docs/BACKLOG.md` и `docs/STATE.md` в этом репозитории (не дублируем здесь, план на них ссылается).

## Outcome

Довести Creative-сторону сайта (`/fir_tree_art`) до полной готовности и зарелизить на домене `ekaterinarazumova.com` через Vercel. Professional-сторона (`/`) содержательно не дорабатывается — точечно чинится только утечка данных (домен `nickpotapov.com` и чужие кейс-стади в `app/sitemap.ts`/`app/robots.ts`).

**Метрика приёмки:** Екатерина сама открывает живой сайт на реальном домене и говорит «ок». Формальных технических чек-листов (Lighthouse и т.п.) не требуется.

## Решения с интервью (stage-grill, 29.08.2026)

- Professional-сторона «по сути готова» — не трогаем контентно. Единственное исключение — утечка данных (см. ниже), это отдельный изолированный фикс, не открывает Professional-скоуп заново.
- Дедлайна/повода для релиза нет, срок открытый. Уточнить у Екатерины на всякий случай (не блокирует план).
- Хостинг/домен: в коде уже зашит `ekaterinarazumova.com` (`app/layout.tsx`), но домен физически ещё не куплен.
- Разделение труда: Ник — технические/инфра-тикеты, гейт после каждого. Екатерина — контент/визуальные тикеты через свои PR, Ник ревьюит и мержит.

## Подход

Два параллельных потока работы поверх одного бэклога (`docs/BACKLOG.md`), сходящихся в общую приёмку:

```
                     ┌─ STAGE 1: Инфра (Ник) ──────────────┐
main ●──────────────►│ SYS-001 → фикс sitemap/robots →     ├──► STAGE 3: Приёмка
                     │ Vercel deploy → домен (после покупки)│    (Екатерина смотрит live → «ок»)
                     └───────────────────────────────────────┘
                     ┌─ STAGE 2: Контент (Екатерина) ───────┐
                     │ PROTEST-001 → SKETCHES-001 →         │
                     │ MEDIA-001 → REVIEWS-001               │
                     └───────────────────────────────────────┘
```

STAGE 1 и 2 идут параллельно (не пересекаются файлами — см. «Риски»). STAGE 3 стартует, когда оба потока закрыты.
