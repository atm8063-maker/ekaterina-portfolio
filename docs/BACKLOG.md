### CASES-011: «Следующий кейс» открывает новую страницу не сверху, а с середины/низа
- **Статус:** ✅ DONE (02.10.2026)
- **Приоритет:** P1
- **Файлы:** `components/case-page-client.tsx` (общий для Insigma/Contact Real Estate/Honda/Mafia), `components/cases/doors-real-estate-case.tsx`, `electronics-shop-case.tsx`, `house-case.tsx`, `landscape-case.tsx`, `nick-potapov-case.tsx`, `vertex-homes-case.tsx`
- **Описание:** Next.js App Router не всегда сбрасывает позицию скролла при переходе между двумя роутами одного динамического шаблона (`/cases/[slug]` → `/cases/[slug]`) через обычный `<Link>`. При клике «следующий кейс» внизу длинной страницы новая страница открывалась с той же позиции скролла, что и была — то есть сразу в середине/у фотографий, а не сверху.
- **Решение:** добавлен `useEffect(() => window.scrollTo(0, 0), [slug])` в `CasePageClient` (с зависимостью от `slug`, так как этот компонент может переиспользоваться между похожими кейсами) и `useEffect(() => window.scrollTo(0, 0), [])` в каждый из 6 отдельных кейс-компонентов (они всегда монтируются заново при переходе между разными кейсами).
- **Критерии готовности:**
  - [x] Причина найдена (отсутствие сброса скролла при client-side навигации)
  - [x] Фикс применён во всех 7 местах, где рендерится кейс

### CASES-012: Doors Real Estate — тёмное пятно при скролле интерактивного превью макета

- **Приоритет:** P1

Реальные файлы (`figma_exports/0N_scheme_*.png`) — 444×1920px, что при object-contain умещается всего в ~1323px (на типичной мобильной ширине), оставляя ~2177px пустого тёмного пространства внизу контейнера — то самое «тёмное пятно» при докрутке.

### MI-BROWSER-001: Mi Browser на Xiaomi показывает десктопную вёрстку на мобиле
- **Статус:** ✅ DONE (02.10.2026, подтверждено кодом задним числом)
- **Приоритет:** P1
- **Описание:** Прошлый фикс от Антигравити (сессия 43d96298, найдена Ником отдельно) диагностировал 3 причины: (1) `background-attachment: fixed` в `globals.css` — Mi Browser на Android не умеет его обрабатывать, из-за чего текстура распирала страницу вбок; (2) отсутствие `export const viewport` в `app/layout.tsx` — без него Mi Browser «угадывал» размер экрана и форсировал десктопный масштаб; (3) `100svh` в `hero.tsx` — старый движок Mi Browser не знает эту единицу, из-за чего главный экран схлопывался в нулевую высоту или дёргался при скролле.
- **Важно:** этот же фикс (коммит `b4b470b`, «fix(cross-browser): stable viewport meta, remove fixed bg-attachment, dvh/svh hero fallbacks») я уже подтянула с `origin/main` раньше в этой же сессии — просто не связала его с Mi Browser явно, пока Ник не нашёл исходный диалог Антигравити.
- **Критерии готовности:**
  - [x] `background-attachment: fixed` → `scroll` в `app/globals.css` (подтверждено в коде)
  - [x] `export const viewport` с `width: 'device-width', minimumScale: 1, viewportFit: 'cover'` в `app/layout.tsx` (подтверждено, плюс сохранены доп. поля `maximumScale`/`themeColor` из более раннего варианта)
  - [x] `100svh` → `100dvh` с `minHeight: 100svh`-фолбэком для контейнеров hero-секции в `hero.tsx` (подтверждено; оставшиеся `100svh` в файле — это формулы ширины/шрифта, не высота контейнера, другой паттерн бага)
  - [x] Уже задеплоено на `ekaterina-portfolio-154d3i1vt-atm8063-makers-projects.vercel.app`
  - [ ] Финальное подтверждение на реальном Mi Browser всё ещё не проверено вживую — Ник пока сверял только логически (сравнение кода), не кликами с телефона
